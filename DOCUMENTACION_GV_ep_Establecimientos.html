1. 📋 Descripción General

GV_ep_Establecimientos es una clase Swift diseñada para gestionar la sincronización de datos entre una API REST y una base de datos local SwiftData. Proporciona métodos robustos para:

  • ✅ Descarga de datos desde endpoints REST
  • ✅ Validación e imputación de valores por defecto
  • ✅ Sincronización incremental/decremental con base de datos local
  • ✅ Consultas flexibles con ordenamiento y filtrado
  • ✅ Limpieza completa de la base de datos
  • ✅ Detección y reporte de duplicados
  • ✅ Manejo exhaustivo de errores
🎯 Objetivo Principal: Proporcionar una capa de abstracción robusta y reutilizable para la sincronización de datos, minimizando la complejidad en las vistas y garantizando la integridad de los datos.

3. 🔢 Enumeraciones

ENUM ModoCargaBD

Descripción: Define el modo de carga de datos a la base de datos local.

Valor Descripción Comportamiento
.full Carga completa Borra todos los registros existentes y carga los nuevos
.add Agregar Solo agrega registros nuevos, permite duplicados
.inc Incremental Actualiza existentes e inserta nuevos, sin duplicados

ENUM OrdenResultados

Descripción: Define el orden de los resultados en las consultas.

Valor Descripción
.asc Orden ascendente por establecimiento_id
.desc Orden descendente por establecimiento_id

ENUM TipoRegreso

Descripción: Define el tipo de datos a retornar en las consultas.

Valor Descripción
.id Retorna solo los IDs de los establecimientos
.full Retorna todos los campos en formato CSV

4. 🔓 Métodos Públicos

PUBLIC Load_API_Stream_EstabalecimeintosV

Descripción: Carga datos desde el endpoint REST con validación e imputación de valores por defecto.

Parámetros:
Nombre Tipo Descripción
xEndPoint String URL base del endpoint (sin el número de registros)
xNo Int Número de registros a solicitar (usar 100000 para "todos")
Retorna:
Campo Tipo Descripción
resultado String JSON del API o mensaje de error
codigoError Int 0 = éxito, -1 = error
Ejemplo de Uso:
let ep = GV_ep_Establecimientos(modelContext: modelContext) let (json, codigo) = ep.Load_API_Stream_EstabalecimeintosV( xEndPoint: "https://api.ejemplo.com/establecimientos", xNo: 50 ) if codigo == 0 { print("✅ Datos cargados: \(json.count) caracteres") } else { print("❌ Error: \(json)") }

PUBLIC Load_Stream_BDL

Descripción: Carga el stream JSON a la base de datos local con diferentes modos de sincronización.

Parámetros:
Nombre Tipo Descripción
xStream String JSON string obtenido del API
flagIncremental ModoCargaBD Modo de carga: .full, .add, o .inc
Retorna:
Campo Tipo Descripción
resultado String Reporte detallado con 4 secciones: Resumen, Lista CSV, Duplicados, Errores
codigoError Int 0 = éxito, -1 = error fatal, -2 = error parcial
⚠️ Importante: En modo .full, todos los registros existentes serán eliminados antes de insertar los nuevos. Use con precaución.
Ejemplo de Uso:
// Primero, obtener datos del API let (json, codigoAPI) = ep.Load_API_Stream_EstabalecimeintosV( xEndPoint: endpoint, xNo: 100 ) if codigoAPI == 0 { // Luego, cargar a la base de datos let (reporte, codigoBD) = ep.Load_Stream_BDL( xStream: json, flagIncremental: .full ) print(reporte) // Muestra resumen detallado }

PUBLIC Get_Establecimientos

Descripción: Consulta establecimientos de la base de datos local con opciones de ordenamiento y formato.

Parámetros:
Nombre Tipo Descripción
xNo Int Número de registros a retornar
incDec OrdenResultados Orden: .asc o .desc
cRegresa TipoRegreso Formato: .id o .full
Retorna:
Campo Tipo Descripción
resultado String Datos formateados (CSV simple con numerador)
codigoError Int 0 = éxito, -1 = error o BD vacía
Ejemplo de Uso:
// Obtener primeros 10 registros, ascendente, completo let (datos, codigo) = ep.Get_Establecimientos( xNo: 10, incDec: .asc, cRegresa: .full ) print(datos) // Salida: // 1. 34618, CANACO SERVYTUR, Ciudad de México, CDMX, Servicios // 2. 34619, Establecimiento 2, Guadalajara, Jalisco, Comercio // ...

PUBLIC Limpiar_BaseDatos

Descripción: Elimina todos los registros de la base de datos local.

Parámetros:

Ninguno

Retorna:
Campo Tipo Descripción
resultado String Reporte con fecha inicio/fin y registros eliminados
codigoError Int 0 = éxito, -1 = error
🚨 ADVERTENCIA: Esta operación es irreversible. Todos los datos locales serán eliminados permanentemente.
Ejemplo de Uso:
let (reporte, codigo) = ep.Limpiar_BaseDatos() if codigo == 0 { print("✅ Base de datos limpiada") print(reporte) } else { print("❌ Error al limpiar: \(reporte)") }

5. 🔒 Métodos Privados

PRIVATE crearEstablecimientoDesdeJSON

Descripción: Crea una instancia de GV_modeloCont_Establecimientos desde un diccionario JSON.

Validación: Verifica que el campo establecimiento_id exista, de lo contrario lanza un error.

PRIVATE actualizarEstablecimiento

Descripción: Actualiza los campos de un establecimiento existente con datos del JSON.

Uso: Utilizado en modo .inc (incremental) para actualizar registros existentes.

PRIVATE obtenerFechaFormateada

Descripción: Retorna la fecha y hora actual en formato ddMMyy HH:mm:ss.

Ejemplo: 110125 14:30:45

6. ⚠️ Manejo de Errores

Códigos de Error

Código Significado Acción Recomendada
0 ✅ Éxito total Operación completada sin errores
-1 ❌ Error fatal La operación falló completamente. Revisar mensaje de error.
-2 ⚠️ Error parcial Algunos registros fallaron, pero el proceso continuó. Revisar reporte detallado.

Estructura del Mensaje de Error

// Formato estándar de error: "Descripción del error, número sistema del error (1001, 1002, etc.), número de establecimiento_Id donde ocurrió el error, fecha y hora (ddMMyy HH:mm:ss), nombre de archivo desde donde se invocó, función del objeto donde ocurrió el error"

Detección de Duplicados

🔍 Análisis Automático: El método Load_Stream_BDL detecta automáticamente duplicados en el JSON del API antes de intentar insertarlos en la base de datos.

Reporte de Duplicados:

  • Lista de IDs duplicados con su frecuencia
  • Ordenados de mayor a menor frecuencia
  • Incluido en la sección 3 del reporte de Load_Stream_BDL

7. 💡 Ejemplos de Uso

Ejemplo 1: Sincronización Completa (API → BD)

// 1. Inicializar el objeto let ep = GV_ep_Establecimientos(modelContext: modelContext) // 2. Descargar datos del API let endpoint = "https://api.ejemplo.com/establecimientos" let (json, codigoAPI) = ep.Load_API_Stream_EstabalecimeintosV( xEndPoint: endpoint, xNo: 100000 // Todos los registros ) guard codigoAPI == 0 else { print("❌ Error en API: \(json)") return } // 3. Cargar a la base de datos (modo FULL) let (reporte, codigoBD) = ep.Load_Stream_BDL( xStream: json, flagIncremental: .full ) print(reporte) // 4. Verificar resultados let (consulta, codigoConsulta) = ep.Get_Establecimientos( xNo: 5, incDec: .asc, cRegresa: .full ) print("Primeros 5 registros:\n\(consulta)")

Ejemplo 2: Actualización Incremental

// Actualizar solo registros nuevos o modificados let ep = GV_ep_Establecimientos(modelContext: modelContext) let (json, codigoAPI) = ep.Load_API_Stream_EstabalecimeintosV( xEndPoint: "https://api.ejemplo.com/establecimientos", xNo: 50 ) if codigoAPI == 0 { let (reporte, codigoBD) = ep.Load_Stream_BDL( xStream: json, flagIncremental: .inc // Modo incremental ) if codigoBD == 0 { print("✅ Actualización incremental exitosa") } else if codigoBD == -2 { print("⚠️ Actualización con errores parciales") } print(reporte) }

Ejemplo 3: Consultas Avanzadas

let ep = GV_ep_Establecimientos(modelContext: modelContext) // Consulta 1: Últimos 10 IDs let (ids, _) = ep.Get_Establecimientos( xNo: 10, incDec: .desc, cRegresa: .id ) print("IDs:\n\(ids)") // Consulta 2: Primeros 20 registros completos let (completo, _) = ep.Get_Establecimientos( xNo: 20, incDec: .asc, cRegresa: .full ) print("Datos completos:\n\(completo)")

Ejemplo 4: Limpieza y Recarga

let ep = GV_ep_Establecimientos(modelContext: modelContext) // 1. Limpiar base de datos let (reporteLimpieza, codigoLimpieza) = ep.Limpiar_BaseDatos() if codigoLimpieza == 0 { print("✅ BD limpiada") print(reporteLimpieza) // 2. Recargar datos frescos let (json, codigoAPI) = ep.Load_API_Stream_EstabalecimeintosV( xEndPoint: "https://api.ejemplo.com/establecimientos", xNo: 100000 ) if codigoAPI == 0 { let (reporte, _) = ep.Load_Stream_BDL( xStream: json, flagIncremental: .full ) print(reporte) } }

8. ✨ Mejores Prácticas

✅ Recomendaciones

  • Usar modo incremental (.inc): Para actualizaciones frecuentes sin perder datos existentes
  • Validar códigos de error: Siempre verificar el código de retorno antes de proceder
  • Manejar errores parciales (-2): Revisar el reporte detallado cuando ocurran
  • Usar 100000 para "todos": Cuando se necesite cargar todos los registros disponibles
  • Ejecutar en Task/async: Para operaciones largas, usar concurrencia de Swift
  • Actualizar UI en MainActor: Después de operaciones asíncronas
  • Revisar duplicados: Analizar la sección 3 del reporte de Load_Stream_BDL

⚠️ Precauciones

  • Modo .full: Elimina TODOS los datos existentes. Usar con precaución.
  • Limpiar_BaseDatos: Operación irreversible. Confirmar antes de ejecutar.
  • Modo .add: Permite duplicados. Solo usar cuando sea necesario.
  • Conexión de red: Verificar conectividad antes de llamar métodos API
  • Tamaño de datos: Para grandes volúmenes, considerar paginación

💡 Optimizaciones

  • Formato CSV simple: Get_Establecimientos usa formato ligero para mejor rendimiento
  • Guardado individual: En modo .full, cada registro se guarda inmediatamente para evitar conflictos
  • Detección temprana de duplicados: Se analizan antes de intentar insertar
  • Consultas limitadas: Usar xNo apropiado para evitar cargar demasiados datos en UI
