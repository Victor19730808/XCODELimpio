🚀 Introducción

La versión V2.0.0.2 introduce tres sistemas centralizados que revolucionan la arquitectura de la aplicación:

🎯 Objetivos de los Sistemas Centralizados:

  • Consistencia Visual: Diseño unificado en toda la aplicación
  • Mantenimiento Simplificado: Cambios centralizados en lugar de archivos dispersos
  • Escalabilidad: Arquitectura preparada para crecimiento futuro
  • Experiencia de Usuario: Interfaz responsive y adaptable
  • Desarrollo Ágil: Componentes reutilizables y configurables
📁 limpioCS/ ├── 📁 GV_desig/ # Sistema de Temas Dinámico ├── 📁 GV_headers/ # Sistema de Encabezados Responsive ├── 📁 GV_menu/ # Sistema de Menús Centralizado └── 📁 [vistas existentes] # Vistas migradas a los nuevos sistemas

🎨 Sistema de Temas Dinámico

El Sistema de Temas permite cambiar la apariencia de toda la aplicación en tiempo real sin reiniciar. Incluye 3 temas predefinidos y arquitectura para agregar más.

📁 Estructura de Archivos

📁 GV_desig/ ├── 📄 ThemeProtocol.swift # Protocolo base para temas ├── 📄 ThemeManager.swift # Gestor singleton de temas ├── 📄 ThemeViewModifier.swift # Modificadores SwiftUI ├── 📄 ThemeSelectorView.swift # Selector de temas └── 📁 Themes/ ├── 📄 ClaroTheme.swift # Tema claro (default) ├── 📄 OscuroTheme.swift # Tema oscuro └── 📄 BuenFinTheme.swift # Tema El Buen Fin

🔧 ThemeProtocol

Define la estructura base que deben implementar todos los temas:

protocol Theme { var name: String { get } var colors: ColorTheme { get } var fonts: FontTheme { get } } struct ColorTheme { let primary: Color let secondary: Color let background: Color let surface: Color let cardBackground: Color let textPrimary: Color let textSecondary: Color let textOnPrimary: Color let shadow: Color } struct FontTheme { let largeTitle: Font let title: Font let headline: Font let body: Font let subheadline: Font let caption: Font }

⚙️ ThemeManager

Gestor singleton que controla el tema activo y permite cambios dinámicos:

class ThemeManager: ObservableObject { static let shared = ThemeManager() @Published var currentThemeType: ThemeType = .claro @Published var currentTheme: Theme = ClaroTheme() private init() { loadSavedTheme() } func setTheme(_ type: ThemeType) { currentThemeType = type currentTheme = createTheme(for: type) saveTheme() } // Métodos privados para persistencia private func loadSavedTheme() { /* ... */ } private func saveTheme() { /* ... */ } private func createTheme(for type: ThemeType) -> Theme { /* ... */ } }

💡 Ejemplo de Uso:

struct MyView: View { @ObservedObject private var themeManager = ThemeManager.shared var body: some View { VStack { Text("Mi Título") .font(themeManager.currentTheme.fonts.title) .foregroundColor(themeManager.currentTheme.colors.textPrimary) Button("Cambiar Tema") { themeManager.setTheme(.oscuro) } .background(themeManager.currentTheme.colors.primary) } .background(themeManager.currentTheme.colors.background) } }

🔧 HeaderManager

Gestor singleton que proporciona acceso a las configuraciones:

class HeaderManager { static let shared = HeaderManager() private let configuration = HeaderConfiguration() private init() {} func getStyle(for type: HeaderType) -> HeaderStyle { return configuration.getStyle(for: type) } func adaptiveFontSize(for type: HeaderType, availableWidth: CGFloat, text: String) -> CGFloat { return configuration.adaptiveFontSize(for: type, availableWidth: availableWidth, text: text) } }

📱 HeaderView

Componente principal que renderiza encabezados responsive:

struct HeaderView: View { let text: String let type: HeaderType let textColor: Color let backgroundColor: Color @State private var availableWidth: CGFloat = 0 private let headerManager = HeaderManager.shared var body: some View { GeometryReader { geometry in let style = headerManager.getStyle(for: type) let adaptiveFontSize = headerManager.adaptiveFontSize( for: type, availableWidth: geometry.size.width, text: text ) Text(text) .font(.system(size: adaptiveFontSize, weight: style.fontWeight, design: .default)) .foregroundColor(textColor) .lineLimit(style.lineLimit) .truncationMode(style.truncationMode) .minimumScaleFactor(style.minScaleFactor) .multilineTextAlignment(.center) .frame(maxWidth: .infinity) .background(backgroundColor) } } }

🍔 Sistema de Menús Centralizado

El Sistema de Menús permite configurar opciones de menú hamburguesa por tipo de vista, manteniendo consistencia y permitiendo personalización contextual.

📁 Estructura de Archivos

📁 GV_menu/ ├── 📄 MenuConfiguration.swift # Configuración de opciones por vista ├── 📄 MenuItem.swift # Estructura de opciones de menú ├── 📄 MenuManager.swift # Gestor singleton └── 📄 HamburgerMenuView.swift # Componente reutilizable

⚙️ MenuConfiguration

Define qué opciones de menú están disponibles para cada tipo de vista:

enum ViewType: String, CaseIterable { case main = "Main" // PORT_PASO, ContentView case map = "Map" // MapView, MapClustersView case list = "List" // EstablecimientosListaView case favorites = "Favorites" // FavoritosView case promotions = "Promotions" // PromocionesView } enum MenuOption: String, CaseIterable { case themes = "themes" case adminDatos = "adminDatos" case advancedSearch = "advancedSearch" case mySettings = "mySettings" } class MenuConfiguration { private let configurations: [ViewType: [MenuOption]] = [ .main: [.themes, .adminDatos, .advancedSearch, .mySettings], .map: [.themes, .advancedSearch, .mySettings], // Sin Admin Datos .list: [.themes, .adminDatos, .mySettings], // Sin Búsquedas Avanzadas .favorites: [.themes, .adminDatos, .advancedSearch, .mySettings], .promotions: [.themes, .adminDatos, .advancedSearch, .mySettings] ] }

🔧 MenuManager

Gestor singleton que proporciona acceso a las configuraciones de menú:

class MenuManager { static let shared = MenuManager() private let configuration = MenuConfiguration() private init() {} func getMenuOptions(for viewType: ViewType) -> [MenuOption] { return configuration.getOptions(for: viewType) } func isOptionEnabled(_ option: MenuOption, for viewType: ViewType) -> Bool { return configuration.isOptionEnabled(option, for: viewType) } func createMenuItems(for viewType: ViewType, actions: [MenuOption: () -> Void]) -> [HamburgerMenuItem] { let enabledOptions = getMenuOptions(for: viewType) return enabledOptions.compactMap { option in guard let action = actions[option] else { return nil } return HamburgerMenuItem(option: option, action: action) } } }

📱 HamburgerMenuView

Componente reutilizable que renderiza el menú hamburguesa:

struct HamburgerMenuView: View { let viewType: ViewType let menuActions: [MenuOption: () -> Void] let iconColor: Color let backgroundColor: Color let shadowColor: Color private let menuManager = MenuManager.shared var body: some View { Menu { ForEach(menuManager.getMenuOptions(for: viewType), id: \.self) { option in Button { menuActions[option]?() } label: { Label(option.displayName, systemImage: option.iconName) } } } label: { Image(systemName: "line.3.horizontal") .font(.title2) .foregroundColor(iconColor) .padding(12) .background( Circle() .fill(backgroundColor) .shadow(color: shadowColor, radius: 4, x: 0, y: 2) ) } } }

🔧 Troubleshooting

Problemas Comunes y Soluciones

❌ Error: "Division by zero" en HeaderConfiguration

Causa: El ancho disponible es 0 cuando se calcula el tamaño de fuente adaptativo.

Solución: Ya está corregido en V2.0.0.2 con validaciones:

// El código ya incluye esta validación: guard availableWidth > 0 else { return baseFontSize }

❌ Error: "Cannot find 'ThemeManager' in scope"

Causa: Falta importar o inicializar ThemeManager.

Solución:

// Agregar en la vista: @ObservedObject private var themeManager = ThemeManager.shared

❌ Error: "Value of type 'View' has no member 'themed'"

Causa: Falta importar ThemeViewModifier.

Solución: Asegurarse de que el archivo esté incluido en el target.

❌ Menú no muestra opciones

Causa: El ViewType no está configurado correctamente.

Solución:

// Verificar que el ViewType esté en MenuConfiguration: private let configurations: [ViewType: [MenuOption]] = [ .miVista: [.themes, .mySettings] // ← Agregar aquí ]

❌ Encabezado se corta

Causa: El texto es muy largo para el espacio disponible.

Solución: El sistema ya maneja esto automáticamente con escalado, pero puedes:

// 1. Cambiar el tipo de encabezado: HeaderView(text: "Texto muy largo", type: .section, ...) // En lugar de .main // 2. ⭐ Mejores Prácticas

🎨 Sistema de Temas

✅ DO (Hacer):

  • Siempre usar @ObservedObject private var themeManager = ThemeManager.shared
  • Aplicar colores y fuentes del tema: themeManager.currentTheme.colors.primary
  • Usar modificadores cuando sea posible: .themed(), .cardStyle()
  • Reaccionar a cambios de tema con onChange
  • Probar todos los temas antes de hacer commit

❌ DON'T (No hacer):

  • No usar colores hardcodeados: Color.blue
  • No crear múltiples instancias de ThemeManager
  • No olvidar aplicar el tema a todos los elementos visuales
  • No usar fuentes hardcodeadas: Font.title

📝 Sistema de Encabezados

✅ DO (Hacer):

  • Usar .main para títulos de pantalla
  • Usar .section para encabezados de contenido
  • Combinar con temas: HeaderView.themed()
  • Probar con textos largos y cortos
  • Verificar en diferentes tamaños de pantalla

❌ DON'T (No hacer):

  • No usar Text() directamente para encabezados importantes
  • No ignorar el escalado automático
  • No mezclar tipos de encabezado sin razón
  • No olvidar el GeometryReader para el escalado

🍔 Sistema de Menús

✅ DO (Hacer):

  • Usar el ViewType correcto para cada vista
  • Definir todas las acciones del menú
  • Usar HamburgerMenuView.themed() cuando sea posible
  • Agregar sheets para las acciones del menú
  • Mantener consistencia en las acciones entre vistas similares

❌ DON'T (No hacer):

  • No hardcodear opciones de menú
  • No olvidar configurar las acciones
  • No usar ViewType incorrecto
  • No crear menús personalizados sin razón

🏗️ Arquitectura General

✅ DO (Hacer):

  • Mantener la separación de responsabilidades
  • Usar los sistemas centralizados consistentemente
  • Documentar cambios importantes
  • Probar en diferentes temas y configuraciones
  • Mantener el código limpio y legible

❌ DON'T (No hacer):

  • No modificar los archivos base sin documentar
  • No crear sistemas paralelos
  • No ignorar las mejores prácticas establecidas
  • No hacer cambios sin probar
